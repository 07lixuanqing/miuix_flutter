# 当前界面问题与优化建议

审查日期：2026-09-07。源码基点：`d7a601e`（`fix: restore gradient top bar glass`）。

后续参考对照：2026-09-08 新增 [ChuxinNeko/flutter_miuix 项目对比](CHUXINNEKO_REFERENCE_COMPARISON_ZH.md)，记录保留的本地克隆、可借鉴的实现、不能直接替换的部分及验证限制。

本文回答底部 Tab、顶部标题区域、其他控件的模糊效果应如何优化，并给出问题证据、优先级和验收方法。本轮交付为审查文档，所列优化尚未实施。默认设计依据为 [HyperOS 4 项目设计基线](HYPEROS4_OFFICIAL_APP_DESIGN_SPEC_ZH.md)，不是旧版 MIUIX 示例外观。

## 1. 总体判断

当前库已经具备真实背景模糊、局部悬浮底栏、大标题折叠、独立圆形操作按钮、五档玻璃和多类弹层材质。2026-09-10 已修复液态底栏选中项缺少局部模糊、小标题顶栏按钮内外轮廓和选中材质不一致，以及紧凑标题栏底部出现整齐模糊截断线的问题。下一步的重点是统一其余能力的默认行为，并补足真机视觉和运行验证。

最值得优先处理的是：

1. **底栏默认入口不统一。** 接入文档推荐 58/52dp 的 `MiuixFloatingNavigationBar`，示例使用 56/48dp 的 `MiuixIosLiquidGlassNavigationBar`。尺寸、材质和交互存在两条实现路线。
2. **顶部仍有清晰度断层。** 当前默认模式是“整区均匀模糊 + 渐变着色”，并不是真正沿垂直方向减弱的模糊。下边界外立即恢复清晰。
3. **五档玻璃没有统一的感知尺度。** 液态主胶囊、独立操作按钮、普通内容表面和临时弹层使用不同倍率；部分差异合理，但同一底栏内部也不一致。
4. **缺少按背景内容调节可读性的机制。** 当前根据主题和所选档位计算透明度，没有根据真实背景明暗、复杂度自动调整遮罩的闭环。
5. **证据需要补强。** 两张带 `final` 的运行截图实际上是启动画面；现有 Golden 也不能替代 Android arm64 Release 的 GPU、触感和帧耗时验证。

优化目标：底栏是一块完整、稳定且能辨认选中项的局部玻璃；顶部在保证标题清楚的同时平滑融入正文；内容控件用克制的层级组织信息，弹层才承担更明确的浮起和遮挡关系。

## 4. 底部 Tab 应该如何优化

### 4.1 先统一默认入口

当前实现并非“底栏还没有悬浮、没有模糊、没有等分”。这些能力已经存在，不能重复算作未完成。

| 项目 | 示例实际使用的液态底栏 | 接入指南推荐的普通悬浮底栏 |
| --- | --- | --- |
| 类名 | `MiuixIosLiquidGlassNavigationBar` | `MiuixFloatingNavigationBar` |
| 默认面板 / 选中层 | 56 / 48dp | 58 / 52dp |
| 内边距 | 4dp | 水平 6dp，上下由高度差形成 |
| 基础背景模糊 | 8 | 主题默认 28 |
| 参数来源 | 多项私有常量和 geometry 分支 | `MiuixHyperOs4Tokens` |
| 独立圆形操作 | 有 trailingAction | 不是同一套 API |

证据：`navigation_bars_ios.dart` 的 `_panelHeight`、`_indicatorHeight`、`_buildPanel`；`hyperos4_tokens.dart` 构造默认值；`reference_bottom_navigation_transition.dart`；现有 [接入说明](CURRENT_UI_IMPLEMENTATION_AND_USAGE_ZH.md) 第 4 节。

**推荐方案：统一默认实现并提供明确兼容入口。** 新默认沿用项目 56dp 面板、4dp 内边距、48dp 选中镜片；示例、集成示例和主题调整都应作用于这一实现。可以增加语义清楚的公共入口或适配现有入口，最终命名在实施时确认。不要直接删除旧类或悄悄改变 `.source` 的 64/56dp 合约。

另一种方案是长期保留两套新默认，但这样每次修复都要分别维护材质、手势和尺寸，不建议。只修改示例视觉也无法解决库使用者的差异。

### 4.2 正确的静态层级

从后到前应为：滚动正文 → 胶囊自身的局部阴影 → 完整胶囊背景模糊与色调 → 单个移动选中面 → 清晰图标和文字 → 短暂触点光。

- 外轮廓只负责把底栏与背景分开，保持连续，避免上半区和下半区形成两种材质。
- 选中面提供稳定的辨认依据。浅色下弱暗色、深色下弱亮色是当前已有策略；进一步调校时先量可读性，不要为增强“液态感”恢复常驻双描边或白色光环。
- 图标和文字始终在采样层之上，不参与镜片模糊。
- 非选中图标可以稍弱于选中图标，但不能因背景复杂而消失。选中状态同时通过镜片、图标样式和颜色表达。
- 圆角外和系统手势区继续透明；正文尾部预留可滚动空间，最后一行应能完全滚到导航上方并点击。
- 两三个目的地可使用独立圆形操作，仍保持 56dp 等高和 12dp 透明间隔；四五个目的地优先保留足够的等分宽度。

以上几何是项目当前基线，不建议仅凭“更像玻璃”的感觉重新加高、压矮或加大阴影。

### 4.3 修复同一底栏内的五档差异

当前主胶囊用 `MiuixGlassIntensity.resolveBlur(8)` 和 `resolveOpacity(.4)`；独立按钮通过 `MiuixGlass` 使用 navigation 配方，基础值为 blur 4、opacity .4。以最强档为例：

| 表面 | 标准档 sigma / 着色 alpha | 最强档 sigma / 着色 alpha |
| --- | --- | --- |
| 主胶囊 | 8 / .400 | 18 / .088 |
| 独立圆形操作 | 4 / .400 | 4.96 / .064 |

这是从当前代码计算的参数，不是屏幕最终透明度；叠加背景与高光还会改变观感。问题不在于两个表面必须用同一个 sigma，而是它们目前沿两套倍率变化，没有明确的角色说明或同场景校准证据。

建议主胶囊和独立操作共享同一材质配方及档位插值，必要差别由语义角色表达。强档以透色、边缘识别和背景柔化的综合效果升级，不能只让主胶囊越来越糊。Android 继续使用已存在的直接 `BackdropFilter` 稳定路径；源码当前明确禁止 Android runtime lens，这一保护不能仅凭桌面 Golden 通过就移除。

### 4.4 动态效果保留什么、完善什么

现有跟手位置更新、释放后吸附、取消回位、RTL、禁用项和减少动态效果的处理应保留。优化前先核对回归用例，避免把已经解决的行为重新做坏。

建议重点验收：

1. 按下先给局部反馈，确认点击才提交目标；拖动逐帧跟手，释放只执行一次吸附。
2. 目标由松手位置决定，速度用于形变与吸附初速度，不把用户甩到相邻项。
3. 取消、移出区域、切换窗口、目的地列表变化后，镜片尺寸、亮度和选中状态都能回到一致状态。
4. 远距离点击页面直接淡出/替换/淡入；内容区横滑仍跟随手指，Slider 等内部控件保留自己的横向手势。
5. 键盘 Tab 移动焦点时显示焦点环，Enter/Space 才提交选择；焦点环与当前选中镜片可以出现在不同项。

当前 N3 的依据是 `_buildTab` 虽使用 `FocusableActionDetector`，却没有接入焦点和悬停状态绘制；任意业务传入的自定义图标可能自行绘制焦点，但组件本身没有保证。Flutter 对此类控件的用法见 [FocusableActionDetector 官方文档](https://api.flutter.dev/flutter/widgets/FocusableActionDetector-class.html)。

### 4.5 大字体和窄窗

当前图文模式按固定 48dp 内容高度布局。图标 22 + 间隔 1 + 文字 11，在文字线性放大到 3 倍时需要约 56dp；这是溢出风险推导，不是本轮已经复现的设备错误。

建议建立普通字号、1.3、2.0、3.0 倍等测试场景。正常字号维持 56/48dp，大字号允许面板增高或进入自适应导航布局，并同步更新正文、Snackbar 和安全区避让。不得为了守住高度而强制把用户字体缩回原值。长标签允许省略但保留完整语义，桌面可提供完整提示。

## 5. 顶部标题区域应该如何优化

### 5.1 已具备的正确基础

当前默认 `gradient` 从首帧提供真实背景模糊；标题和按钮在独立前景层。2026-09-11 修复后，滤镜不仅按布局高度限制为“顶部安全区 + 标题行”，还通过独立矩形裁剪锁定实际合成域；同一个顶栏容器中的搜索栏等底部内容以及页面正文均不参与模糊。紧凑标题材质在自身顶部 68% 范围保持完整磨砂，随后使用项目校准的可变半径模糊平滑衰减到标题区域底边的 0，颜色遮罩同步渐隐，避免固定半径 `BackdropFilter` 在矩形底边形成清晰分界。右侧每个操作使用 44dp 可见圆形玻璃和 48dp 交互目标，可见圆之间保持 8dp 间隔；两个按钮的布局宽度为 100dp。选中态使用 14% 主题色透明覆盖并同步图标主题色，按压反馈也裁剪到同一个圆形轮廓，不再出现 48dp 玻璃外圈套 44dp squircle 的双层形状。大标题 32sp、小标题 20sp 的当前角色，以及首屏正文避让、Sliver 折叠能力均已存在。68% 起始位置和 0.8 衰减曲线均为项目截图校准值，不宣称为小米官方公开参数。

这些不应重新列作“待支持”，也不建议把多个操作重新合并成一整块椭圆胶囊。

### 5.2 当前的渐变为什么仍可能像一条横栏

`_MiuixProgressiveTopBarGlass` 目前在整个 `ClipRect` 内使用相同 sigma。它的 child 是三段着色渐变，停点为 `[0, .56, 1]`，透明度比例为 `[1, .58, .22]`。因此：

- 上下颜色可以平滑变化，但上下模糊半径并未随位置变化。
- 到滤镜裁剪边界时，后方内容从模糊直接恢复清晰。
- 大标题展开时，材质范围随整块内容增长，可能形成较大的灰白雾区。

当前 [顶栏测试基准图](../test/goldens/top_app_bar_gradient_android.png) 在高度 52px 处显示模糊区结束，下方彩条立即锐利；这是测试画布中的像素位置，不能当成真机 dp。现存 [2026-09-01 折叠态运行截图](../artifacts/parity/miuix_top_home_android_20260901.png) 也可看到标题下方的明确边界。它只支持该历史画面的观察，不证明本轮新包的表现。

### 5.3 推荐的视觉结构

紧凑标题和状态栏后方保留持续可见的磨砂核心区；靠正文处增加短而连续的过渡带，使着色与模糊分别衰减。文字进入过渡带时先变柔，再进入标题核心区，不应突然被切成上下两种清晰度。

大标题本身主要属于页面内容层。展开时可与搜索、筛选形成清楚的纵向关系；紧凑操作区保持稳定位置。不要为了“轻盈”让首屏完全失去材质，也不要把整个大标题留白都染成相同浓度。

过渡带的高度和衰减曲线需按同尺寸画面校准，本次不编造“官方”参数。验收应比较每行背景高频信息的衰减，而不仅是看渐变颜色是否存在。

### 5.4 实现路线及取舍

| 路线 | 价值 | 边界 |
| --- | --- | --- |
| 保留直接单滤镜，优化着色、范围和布局 | 风险较低，可先统一外观 | 均匀滤镜仍存在边界，不能称为真正连续的模糊衰减 |
| 经设备验证的连续渐进模糊 | 能同时改善着色与清晰度衔接，推荐作为目标 | 需要真实背景采样和 Android GLES/Vulkan、Windows 后端验证 |
| 多个横条分别设置 blur | 容易快速做出近似 | 易产生条带和多次合成，不作为默认方案 |

库中已有 `MiuixProgressiveLayerBackdrop` 及运行时/回退路径，可作为评估起点，但不能直接视为可安全替换顶栏。此前记录的失效涉及滤镜外侧 `ColorFiltered`、透明离屏层以及 runtime shader 的输入坐标。新的方案必须先证明后方内容仍能真实取样。

尤其不能简单把整个 `BackdropFilter` 包进 `Opacity` 或 `ShaderMask`，然后用颜色渐隐测试通过来代替 arm64 验证。Flutter 官方也说明临时合成层会影响滤镜混合结果，详见 [BackdropFilter 文档](https://api.flutter.dev/flutter/widgets/BackdropFilter-class.html)。

### 5.5 标题运动和操作区

- 普通默认入口与 Sliver 入口统一标题角色、对齐线、展开/收起高度和副标题规则；状态栏 inset 只消费一次。
- 大小标题由同一个折叠进度协调，连续插值位置与透明度，避免慢拖、反向滚动时独立时间动画追赶手指。来源兼容模式可保留当前三分之一阈值和 20 物理像素位移。
- 长标题、两个及以上操作、返回按钮、副标题、RTL 和大字体分别验收；优先保留标题可读空间，次要操作可进入更多菜单。
- 圆形按钮可保留比底面更清楚的边缘，但不应因底面模糊一次、按钮再模糊一次而变成浓白圆饼。先比较它采样到的是正文还是已着色的顶栏，再决定复用采样或降低额外模糊。
- 大标题语义与小标题语义需随可见状态协调，检查读屏顺序，避免视觉上一个标题却重复播报。

## 6. 其他控件的模糊效果应该如何优化

### 6.1 按角色统一，不按控件各自调感觉

当前已经有 `MiuixGlassOptics.navigation` 和 `.transient`，这比所有控件共用一个 sigma 更合理。接下来应把内容表面、输入表面及自适应策略也纳入同一体系。

| 控件 / 角色 | 推荐材质目标 | 应避免的处理 |
| --- | --- | --- |
| 顶栏、底栏、浮动工具栏 | 稳定局部采样、克制着色、能识别边缘 | 全宽实体底板、持续发白的边缘、反复采样前景文字 |
| 搜索与输入框 | 保证占位文字、正文、光标及焦点清楚；聚焦态主要改变边界和对比 | 聚焦就大幅加 blur，或透明到背景文字干扰输入 |
| 设置组、普通卡片 | 低对比表面，一组内容拥有一个材质容器 | 每一行再包玻璃，产生卡片套卡片与重复高光 |
| 菜单、Dropdown、Tooltip、Snackbar | 使用 transient 角色，表面边界清楚，阅读优先 | 内部列表再加一层玻璃；最强档文字贴着复杂背景 |
| Dialog、BottomSheet | 面板拥有局部玻璃，遮罩负责压低背景，内容层保持清晰 | 全屏玻璃遮罩；面板、卡片、输入框无差别重复模糊 |
| 日历、Picker、数据表、树 | 内容密度优先；容器可弱玻璃，单元格与行以状态色和分隔组织 | 逐单元格/逐行建立滤镜；滚动时不停变更透明度 |
| Button、Switch、Checkbox、Slider、进度 | 强调状态、热区和动效，必要时使用透明或实体色 | 为统一“玻璃感”给所有轨道、滑块和图标都添加背景滤镜 |

原生表面级模糊与只模糊某张装饰图片是不同任务；后者可以评估 `ImageFiltered`，不能用它替换需要真实页面采样的玻璃。依据同上 Flutter 官方文档。

### 6.2 当前五档参数的实际差异

下表为当前代码值的计算结果，alpha 假设原始色自身为不透明；不等于最终屏幕像素，也不代表全部控件的实际视觉已测量。

| 示例角色 | 标准档 sigma / alpha | 最强档 sigma / alpha | 当前来源 |
| --- | --- | --- | --- |
| 渐变顶栏顶部 | 28 / .580 | 34.72 / .0928 | navigation 配方；下缘 alpha 再乘 .22 |
| 液态主胶囊 | 8 / .400 | 18 / .088 | 通用配方 |
| 普通内容玻璃，使用默认 token 且未指定 optics | 24 / .680 | 54 / .1496 | 通用配方 |
| 搜索框 | 18 / .620 | 40.5 / .1364 | 通用配方 |
| Dialog | 30 / .5576 | 36 / .1224 | transient 配方 |

不能由此直接断言哪个控件一定卡顿，但能确认“最强档”目前代表不同的倍率变化。建议把五档定义为统一的感知目标，配方仍按角色区别：

1. 最弱：少量模糊、较稳定着色、保守高光。
2. 较弱：轮廓清楚，轻微透色。
3. 标准：阅读与透色平衡，作为主要校准基准。
4. 较强：增强背景色感，适当减弱实体覆盖，不用大幅提高 sigma。
5. 最强：保留明显通透感，同时受可读性下限约束；复杂背景下允许局部加强遮罩。

档位切换应平滑插值 blur、tint 和边缘，响应减少动态效果。不要要求每个参数都线性增加，也不要要求最强档在所有背景上都使用最低透明遮罩。

### 6.3 补足内容感知与无障碍回退

`MiuixGlass.build` 当前根据全局开关、强度、主题色和显式参数计算效果；navigation/transient 本身是固定表。它们能够随主题变化，但不等于根据真实背景内容自适应。

建议分两步实现：

1. **先提供可控策略。** 由页面提供背景类型、明暗倾向、复杂度提示或可读性需求；未知场景使用保守遮罩。将系统高对比偏好接入材质解析，高对比时优先文字和状态轮廓。
2. **再验证自动估计。** 若加入背景采样，应限制范围和更新频率，并使用平滑、滞回避免快速滚动时透明度闪烁。避免每帧整屏截图读回。读不到有效背景时返回保守配方。

这一策略应实现在 `lib/`，供所有玻璃角色复用。关闭玻璃和开启高对比不是同一个设置；减少动态效果也不应被简单等同于关闭模糊。

### 6.4 合成与性能原则

- 为每一个独立表面明确裁剪形状和背景采样所有者，减少无意的嵌套滤镜。
- 阴影、玻璃和命中区共享几何来源；圆角外不能泄漏矩形颜色或阴影。
- 同背景、互不重叠的滤镜可评估 `BackdropGroup` / grouped 方式；相互重叠的表面不能盲目使用同一个 key，避免层次错误。见 [Flutter 背景滤镜分组说明](https://api.flutter.dev/flutter/widgets/BackdropFilter-class.html)。
- 热点移动尽量只重绘局部光效，镜片移动复用滤镜子树。`MiuixGlass` 当前指针移动会 setState 重建其表面，应测量后决定是否改为局部通知与绘制，不直接把它认定为已发生掉帧。
- 优先按设备能力减少动态光和昂贵折射，保留真正的局部背景柔化及清楚轮廓；不要把所有弱设备统一退成全屏纯色遮盖。
- GPU 预算必须包含顶栏、底栏、滚动内容和弹层同时存在的场景。单独组件静止通过并不充分。可参考 [Flutter 性能实践](https://docs.flutter.dev/perf/best-practices)。

## 7. 其他需要同时整理的问题

### 7.1 示例中的独立搜索操作

`reference_bottom_navigation_transition.dart` 第 67—74 行附近：当导航项不超过三个时出现搜索按钮，回调是 `_selectPage(0)`。库内 trailingAction 自身没有改变索引，但示例回调会这样做。建议让它进入搜索或聚焦搜索字段，导航选中态由真实页面关系决定。

### 7.2 私有常量和文档描述漂移

液态底栏仍有大量独立常量，且 trailingAction 注释仍描述 64dp，而默认 geometry 已是 56dp。接入指南将普通悬浮底栏定义为默认，液态实现源码注释又把普通实现称作兼容入口。应把默认角色、参数来源和兼容边界一次性说清楚。

顶部大小标题参数、Sliver token 和来源物理像素规则也应区分用途，避免主题修改只作用于其中一条实现。

### 7.3 测试通过与视觉达标是两件事

当前顶栏像素测试检查区域内各行发生软化，以及下边缘仍保留模糊；它没有要求“滤镜区域与未滤镜正文之间连续衔接”。所以现有测试通过与 T1 仍成立并不矛盾。

后续应新增针对实际目标的边界连续性、焦点可见性、文字放大和同档位角色一致性验证。不得只更新 Golden 消除差异，必须先确认新画面符合目标。

### 阶段三：跨设备、辅助功能与性能

| 维度 | 最少场景 | 判断方式 |
| --- | --- | --- |

| 输入 | 点击、慢拖、快速拖、取消、禁用项、键盘、鼠标、RTL | 回调次数和目标正确，焦点可见，热区与图形一致 |
