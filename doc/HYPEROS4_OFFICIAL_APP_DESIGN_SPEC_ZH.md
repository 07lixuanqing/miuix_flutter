# HyperOS 4 官方软件风格实施规范

> 基线日期：2026-08-20  
> 适用范围：`flutter_miuix` 组件库、示例程序以及后续使用本库开发的应用。

## 1. 规范地位

从本规范生效起，HyperOS 4 是项目后续新增、重做和视觉修复的默认设计目标。
现有 MIUIX 实现只保留 API、行为和迁移兼容价值，不再作为新界面的视觉基线。

小米当前公开的是产品宣传与功能说明，并不是一份带完整 dp、字号、曲线和材质参数的
开发者设计系统。因此本规范严格区分三类信息：

- **官方明确**：小米 HyperOS 4 官网文字明确说明的设计或能力。
- **官方画面观察**：从官网展示的系统应用、桌面与动效画面中可以直接观察到的结构。
- **项目实施规则**：为了在 Flutter 中稳定复现上述效果而制定的工程约束；不冒充小米公开参数。

网络爆料中提到、但官网没有明确展示或说明的内容，不得以“HyperOS 4 官方规范”的名义
直接写入组件默认值。

## 2. 核心设计语言

### 2.1 生命感美学（官方明确）

界面不能只做成静态的半透明圆角矩形。材质、光线、触摸和位移应形成连续反馈：

- 柔光玻璃根据背景内容呈现不同的色彩、明暗和透明感。
- 点按位置产生局部光感，拖动时光感跟随手指或指针流动。
- 透明度要随背景复杂度自适应，优先保证文字和图标可读。
- 动画应表现连续的空间关系，而不是控件瞬间替换或机械淡入淡出。

### 2.2 内容优先（官方画面观察）

- 页面背景和可滚动内容采用 edge-to-edge，全屏延伸到系统栏及悬浮控件后方。
- 顶部、底部导航是悬浮于内容之上的局部表面，不应用不透明矩形截断整个页面。
- 通过留白、字号、材质和层级建立结构，减少固定色块和多余卡片套卡片。
- 首屏正文默认从大标题下方开始；上滑后内容可以进入标题或顶部玻璃表面后方。

### 2.3 空间连续性（官方明确及画面观察）

- 页面、横竖屏、悬浮窗和应用切换均应保持来源与去向可感知。
- 元素移动、展开、收起和重排优先使用弹性位移、形状插值和共享位置关系。
- 动效结束时应稳定落位，不能出现回弹越界、尺寸跳变或内容闪烁。

## 3. 页面骨架

后续页面默认按以下层级组织：

1. 全屏场景或页面背景。
2. 可滚动主体内容，背景延伸到系统栏与悬浮控件后方。
3. 大标题、页内搜索和主要内容层。
4. 局部悬浮的顶部操作、底部导航及主要操作按钮。
5. Snackbar、菜单、对话框等临时反馈层。

强制要求：

- 正文必须为顶部标题预留初始安全空间，但滚动后允许从顶部材质后方经过。
- 底部必须为导航胶囊高度和系统手势安全区预留可滚动尾部空间。
- 预留空间只能防止内容不可点击，不能用不透明矩形填满悬浮导航周围区域。
- Snackbar、提示条和确认反馈必须显示在底部导航之上，不能被导航遮挡。
- Android 必须同时处理状态栏、导航栏、三键导航与底部手势条；Windows 必须处理窗口边界和标题栏。
- 示例程序只提供一种悬浮导航样式，不再暴露“默认 / iOS 风格”切换；旧组件仅用于公共 API 兼容。
- 悬浮胶囊采用 MIUIX 液态示例的分层材质：真实背景模糊、容器色和边缘高光必须覆盖完整胶囊，不能只让上半部出现一块不同材质；折射仅在运行后端能够稳定采样时启用。
- 默认移动镜片静止时占满一个等宽目的地区域，高度为 48dp；按住拖动时四边约内缩 2dp，并随速度产生受限形变，面板只允许约 4dp 的轻微橡皮筋位移。
- 松手提交手指最终所在槽位的最近项；速度只用于镜片形变和吸附弹簧初速度，不能把实际目标再投射到相邻 Tab。
- 移动镜片可使用独立的按压深度折射、色散和内阴影，但位置帧必须复用已有滤镜子树。Android 实测出现放大彩条或采样错位时必须退回真实背景模糊，不能继续把 GPU 花屏当作液态色散。
- 按压时面板投影保持静止轮廓，只缩放玻璃表面；每个目的地的选中图标和文字必须围绕自身中心缩放，不能把整排内容绕共同中心缩放。静止镜片不得额外常驻一圈高光，内阴影必须贴住同一外轮廓，避免出现分离的双层椭圆。
- HyperOS 4 默认采用本项目按参考真机画面校准的 56dp 面板、4dp 内边距和 48dp 镜片；`source` 兼容入口保留 compose-miuix 液态导航示例源码的 64dp 面板、4dp 内边距和 56dp 镜片。拖动态内缩 2dp 同样是项目推导值，以上数值均不宣称为小米官方公开的 HyperOS 4 设计令牌。

## 4. 顶部区域与标题

### 4.1 默认结构

- 以页内大标题为主要层级，不默认使用一条贯穿全宽的实体 AppBar。
- 常用操作可作为右上角独立图标、圆形或小胶囊悬浮于背景上。
- 紧凑标题区域默认使用持续可见的真实背景磨砂；单个右侧操作使用圆形玻璃面，多个
  相邻操作共用一个胶囊玻璃面。滚动渐显材质只作为显式可选模式保留。
- 大标题下方可紧接搜索框、筛选胶囊或正文；间距保持宽松但不能造成内容断层。
- 滚动折叠后，紧凑标题和操作表面应使用真实背景采样的玻璃材质。

### 4.2 验收

- 静止首屏时正文不与标题重叠。
- 上滑时内容确实能在顶部玻璃后方移动，并能看见模糊后的背景变化。
- 标题折叠、展开和页面切换没有突然跳位。
- 顶部表面之外的区域保持透明并继续显示后方内容。

## 5. 悬浮底部导航

官方系统应用画面显示的是局部胶囊导航，部分场景会搭配独立圆形主操作按钮。
项目实现必须满足：

- 只有胶囊或独立按钮自身绘制玻璃、描边和阴影。
- 独立操作与主胶囊等高并保持清晰间隔；它不是导航目的地，点击后不得移动选中镜片。
- 胶囊外侧、圆角切角处及其上方不得存在补成矩形的背景或阴影层。
- 后方内容在非胶囊区域完全可见，并可在导航后方滚动。
- 多个目的地在中英文、仅图标、仅文字、图标加文字模式下都必须视觉等分。
- 默认目的地采用图标在上、文字在下的纵向内容结构；单项触控区域保持横向等分，悬浮
  液态样式的选中镜片使用同一个等分宽度，不能只围绕图标画成固定小圆。
- 导航整体高度要同时容纳触控热区、图标、文字和选中动效，不得为了“悬浮感”压矮。
- 胶囊宽度根据目的地数量和窗口宽度自适应；不得让任一项因文本长度获得额外布局宽度。
- 底边距叠加系统安全区，但不得把手势条区域涂成导航容器颜色。
- 选中指示器、图标和文字采用连续位移、颜色和形状过渡，避免瞬切。
- 点击相隔多个目的地时，页面内容短暂淡出后直接替换目标并淡入，不得把所有中间
  页面依次横向扫过；只有用户直接拖动页面内容区时，页面才随手指横向移动。
- 项目扩展允许直接左右拖动底栏选中块：指针移动阶段逐帧直跟，不能为每个触点采样
  重启弹簧；松手后只执行一次弹簧吸附。点击未松手前只显示收缩反馈，确认点击后再向
  目标连续移动。松手、取消或系统手势打断后必须可靠回到静止尺寸。

官方画面没有公布统一 dp 数值。具体高度、圆角、边距和阴影须通过官方画面比例测量、
Android 真机/模拟器及 Windows 截图对比确定，不能凭感觉填写后宣称“官方尺寸”。
本项目当前按参考画面推导默认主胶囊 56dp 高、独立操作 56dp 圆形、两者间隔 12dp，
拆分模式每个目的地优先宽 80dp，空间不足时再严格等分收缩；来源兼容入口保留
64dp 高度。这些均为项目推导值。

## 6. 柔光玻璃材质

### 6.1 必须具备的组成

玻璃表面至少由以下层共同构成：

- 对表面后方真实内容的背景模糊，而不是只降低前景颜色透明度。
- 根据背景明暗和主题变化的半透明色调。
- 沿连续圆角轮廓绘制的柔和高光或折射边缘。
- 与裁剪形状完全一致的局部阴影，禁止矩形阴影底板。
- 保证文字、图标和选中态对比度的动态遮罩。
- 点按与拖动位置可感知的局部光效。

### 6.2 五档设置的项目映射

项目现有五档设置继续保留，但它控制的是完整材质配置，而不只是 blur sigma：

1. 最弱：低模糊、较高实体遮罩、无明显折射，优先性能与可读性。
2. 较弱：轻微背景采样和边缘高光。
3. 标准：默认的自适应透明度、模糊和局部高光。
4. 较强：更清晰的背景色感与折射层次，仍须保持文字对比度。
5. 最强：最明显的背景模糊、透色和动态光感；不能退化成纯白或纯色不透明表面。

低性能设备可以降低采样分辨率、动态光数量或刷新频率，但必须保留形状、层级和透明关系，
不能用全屏不透明矩形代替局部玻璃。

### 6.3 导航玻璃的清透校准

Apple 的 iOS 27 官方页面把新版 Liquid Glass 的方向描述为更均匀的折射、更好的对比度，
并提供从 ultraclear 到 fully tinted 的透明度范围。这不是 HyperOS 4 的官方参数，项目仅将
其作为顶栏和底栏光学表现的辅助参照，组件几何、层级和交互仍遵循本规范的 HyperOS 4 基线。

- 强档主要降低实体着色并增强透色，不得无限放大 Gaussian sigma 抹掉背景结构。
- 模糊后保留适度的背景饱和度与对比度，使列表、图片和强调色仍可辨认。
- 高光集中在顶部与起始方向的轮廓，底部与结束方向使用较暗的折射边界。
- 玻璃中心不叠加大面积白色渐变，避免浅色页面再次变成不透明白板。
- 渐进顶栏在下边缘保留微弱扩散，滚动内容进入标题后方时不得出现清晰度断层。
- 本项目的五档倍率、色彩矩阵和边缘透明度均为运行画面校准值，不称为 Apple 官方数值。

## 7. 形状、卡片与列表

- 主要形状家族为连续圆角矩形、超椭圆、胶囊和圆形。
- 同一层级的圆角与轮廓逻辑必须统一，不能混用生硬普通圆角和超椭圆。
- 搜索、筛选和底部快捷操作多使用低高度胶囊；主要按钮可使用圆形或高胶囊。
- 信息卡片可使用轻微染色的玻璃或低对比实体表面，但不是所有列表项都必须包卡片。
- 普通联系人、文件等高密度列表优先使用大留白和弱分隔线，减少重复边框。
- 天气、媒体和实时状态等场景可以使用全屏动态背景加半透明信息卡。
- 列表的索引条、滚动条和侧边控件保持轻量，不应形成第二条实体导航栏。

## 8. 字体、图标与色彩

### 8.1 字体层级

- 页面标题使用明显大于正文的显示级字号和足够留白。
- 时间、温度等核心数字可以使用超大、较轻字重，背景负责提供空间氛围。
- 正文、辅助文本和时间戳形成清楚的三级对比，不依赖大量分割线。
- 不臆造官方字号表；项目 token 应基于角色定义，并通过同尺寸截图校准。

### 8.2 图标

- 官方桌面画面可观察到部分系统图标具有渐变、高光、体积和超椭圆底板。
- 这不等于官网宣布“所有图标统一 2.5D 重绘”。组件库不得强制改造第三方应用图标。
- 控件图标必须检查方向、RTL、旋转和坐标系，禁止出现上下或左右颠倒。
- 线性操作图标保持视觉重量一致；选中态可以通过填充、色彩和局部表面表达。

### 8.3 色彩

- 主题色用于关键选择、主要操作和状态强调，不应大面积覆盖内容。
- 玻璃色调来自背景和场景，不能固定为一块灰白色。
- 所有状态需在浅色、深色、复杂图片背景和高对比模式下验证。

## 9. 动效、手势与触觉

- 点按反馈从触点产生，拖动光效跟随当前指针位置。
- 导航切换、折叠标题、卡片展开和弹层出现使用连续的位移、缩放、形状和透明度组合。
- 拖动被取消时，控件应沿可理解路径回到原位。
- 横竖屏和窗口尺寸变化保持内容锚点，避免整页闪白或重新从中心出现。
- Slider、颜色选择器、日历拖选等横向手势必须优先获得自身手势，不得误触页面横向切换。
- 官方 MIUIX 已有语义明确的震动角色时应调用对应角色；Windows 使用强度和时长相近的安全回退。
- 必须支持“减少动态效果”；关闭动画后仍保留清晰的状态变化和层级。

## 10. 弹层、菜单和反馈

- 下拉菜单、Surface actions 和 Display mode 等弹层锚定触发控件或当前操作点。
- 弹层尺寸由内容和可用窗口决定，不得在内容很少时默认撑满屏幕高度。
- 越界时优先翻转方向、调整偏移或限制最大高度，而不是脱离锚点居中。
- 菜单、对话框和 BottomSheet 的玻璃效果只存在于自身裁剪区域。
- Snackbar 的层级高于悬浮导航，并为系统安全区和导航胶囊共同留出位置。

## 11. 手机、平板与桌面自适应

### 11.1 手机

- 强调沉浸浏览、单手可达和局部悬浮导航。
- 内容可延伸到边缘，但交互热区必须避开系统手势冲突。

### 11.2 平板与宽窗口

- 不能简单等比放大手机布局。
- 使用可切换导航、分栏、主从视图和可调整内容宽度。
- 浮窗与全屏切换保持同一内容的空间连续性。

### 11.3 Windows

- 延续相同材质、层级、形状和动效语言，但适配鼠标悬停、右键、键盘焦点和窗口缩放。
- 玻璃效果采样应用内容；系统级窗口背景材质仅在稳定可用时启用。
- 所有触控目标同时提供合理的鼠标命中范围和焦点可见性。

## 12. 桌面与系统级模式（按适用范围采用）

官网还展示了以下系统模式，它们不是每个普通应用都必须实现的组件：

- 可缩放、可移动的大号锁屏时钟。
- 锁屏底部堆叠通知，上滑展开。
- 可变尺寸文件夹及自动重排。
- 同尺寸小部件堆叠和纵向切换。
- 超级岛实时状态、任务结果自动展开和设备中心。
- 悬浮窗、横竖屏及应用切换的连续动画。

只有组件业务确实涉及锁屏、小部件、实时状态或多设备时，才按相应模式扩展；不得为了
外观相似把普通 AppBar 或通知提示伪装成系统级能力。

## 13. 官网未确认的说法

截至基线日期，官网没有把以下说法列为明确的全局官方规范：

- 控制中心已经采用某一种固定的完整新布局。
- 所有系统与第三方图标都必须统一为“2.5D”。
- 状态栏图标必须统一加粗，或手势条必须缩短为某个固定长度。
- 系统提供名为“透明/柔和”的全局材质切换。

这些项目可以继续研究和实机验证，但在证据完善前不能写成默认组件规范。

## 14. `flutter_miuix` 落地规则

- 现有公共 API 尽量保持源码兼容，但新默认主题迁移到 HyperOS 4 视觉 token。
- 新组件直接使用 HyperOS 4 的页面、材质、形状、动效和自适应规则，不再复制旧示例风格。
- 修改旧组件时同步迁移其默认视觉；确有兼容需求时用明确的 legacy 选项保留，不允许旧样式继续作为默认值。
- 组件能力必须实现在 `lib/` 库中；示例程序只负责展示和回归，不能只在示例里伪造效果。
- 共用参数进入主题扩展或 token 层，禁止在示例页散落重复的颜色、圆角、模糊和动画常量。
- 官网没有数值的参数必须经过参考画面比例测量和运行截图对比，并在代码注释或视觉基线中标为项目校准值。

建议逐步形成以下公共能力（最终命名以项目 API 审核为准）：

- HyperOS 4 主题 token 与材质配置。
- 自适应柔光玻璃表面和五档材质控制器。
